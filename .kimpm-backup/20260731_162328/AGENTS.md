# AGENTS.md
## KimPM Project Execution Rules v1.1

이 파일은 Codex 및 AI 개발 도구가 작업 전에 반드시 확인해야 하는 프로젝트 실행 규칙이다.

## Core Principles
1. 기존 기능을 절대 깨지 않는다.
2. 추측하지 말고 소스·DB·설정·로그를 확인한다.
3. 변경 전 영향 범위를 먼저 분석한다.
4. 작업은 작고 검증 가능한 단위로 수행한다.
5. 코드와 문서를 함께 최신화한다.
6. 가독성·간편성·변경 용이성을 우선한다.
7. 보안과 비밀정보 보호를 기본으로 한다.

## Work Scope
- 작업 시작 전 요구사항, 대상 파일, 영향 범위를 식별한다.
- 프로젝트 전체를 무조건 읽지 않는다.
- 현재 작업과 관련된 파일만 선택적으로 확인한다.
- 관련 없는 리팩터링을 기능 변경과 섞지 않는다.
- 대규모 변경은 작은 단계로 분할한다.

## Maintainability
- 이름만 보고 역할을 이해할 수 있도록 작성한다.
- 한 함수는 하나의 핵심 책임만 가진다.
- 중첩 조건문보다 Early Return을 우선한다.
- 반복되는 값과 로직은 적절히 공통화한다.
- 하드코딩된 업무값, URL, 상태코드, 메시지를 반복하지 않는다.
- 사용되지 않는 코드와 주석은 제거한다.
- 지나친 추상화나 불필요한 계층은 만들지 않는다.

## Comment Rules
- 코드에 이미 보이는 동작을 반복 설명하지 않는다.
- 주석은 Why, 업무 규칙, 예외, 제약, 변경 주의사항을 설명한다.
- 복잡한 알고리즘, 보안 판단, 임시 우회 처리에는 주석을 남긴다.
- 주석과 실제 코드가 불일치하면 즉시 수정하거나 삭제한다.

## Context and Token Efficiency
- 동일한 파일을 이유 없이 반복해서 읽지 않는다.
- 긴 로그는 오류 주변과 핵심 구간만 확인한다.
- 이미 확인한 사실을 반복해서 설명하지 않는다.
- 불필요한 전체 코드 출력과 장황한 요약을 피한다.
- 필요한 경우 상세 문서는 `KIMPM.md`와 `docs/`에서 선택적으로 확인한다.

## Quality Verification
개발 중:
```bash
npm run verify:quick
```

작업 완료 전:
```bash
npm run verify
```

- 검증 실패 상태에서는 작업 완료로 보고하지 않는다.
- 실행할 수 없는 검증 항목은 이유와 미검증 범위를 명확히 보고한다.

## Completion Report
1. 변경 파일
2. 구현 내용
3. 기존 기능 영향
4. 실행한 검증 명령
5. 검증 결과
6. 남은 위험 또는 TODO
