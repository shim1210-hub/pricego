# KimPM Development Constitution v1.0

## 서문

KimPM Development Constitution은 모든 프로젝트에서 반드시 지켜야 하는 최상위 개발 원칙이다.

Framework는 "어떻게 개발할 것인가"를 정의하고,
Constitution은 "무엇을 절대로 지켜야 하는가"를 정의한다.

어떠한 기능 개발도 이 헌법보다 우선하지 않는다.

---

# 제1조 기존 기능을 절대 깨지 않는다.

모든 개발의 최우선 목표는 새로운 기능을 만드는 것이 아니라 기존 서비스를 안정적으로 유지하는 것이다.

원칙

* 기존 기능을 제거하지 않는다.
* 기존 API를 임의 변경하지 않는다.
* 기존 DB 구조를 추측하여 수정하지 않는다.
* 변경 전 영향도를 확인한다.
* 회귀 테스트를 수행한다.

---

# 제2조 추측하여 개발하지 않는다.

모르는 것은 추측하지 않는다.

반드시 확인한다.

확인 대상

* DB 구조
* API
* 환경변수
* 기존 소스
* Git History
* 요구사항

AI의 추측보다 실제 프로젝트가 항상 우선이다.

---

# 제3조 데이터베이스를 먼저 확인한다.

데이터 구조는 시스템의 기준이다.

UI보다 DB를 먼저 이해한다.

확인 순서

업무

↓

ERD

↓

Table

↓

Column

↓

Constraint

↓

Sample Data

↓

CRUD

DB 구조를 확인하지 않고 SQL을 작성하지 않는다.

---

# 제4조 작은 단위로 구현한다.

큰 기능을 한 번에 구현하지 않는다.

반드시

* 작은 작업
* 작은 Commit
* 작은 Review
* 작은 Test

를 반복한다.

하나의 작업은 하나의 목적만 가져야 한다.

---

# 제5조 문서와 코드는 항상 일치해야 한다.

문서는 살아있는 산출물이다.

코드가 변경되면 문서도 함께 변경한다.

대상

* README
* Framework
* Architecture
* DB
* API
* 화면설계
* History

문서와 코드가 다르면 문서를 수정한다.

---

# 제6조 유지보수가 개발보다 중요하다.

읽기 어려운 코드는 좋은 코드가 아니다.

원칙

* 이름은 명확하게 작성한다.
* 중복을 줄인다.
* 함수 하나는 하나의 역할만 수행한다.
* 하드코딩을 최소화한다.
* 불필요한 복잡성을 만들지 않는다.

다음 개발자가 쉽게 이해할 수 있어야 한다.

---

# 제7조 보안은 선택이 아니라 기본이다.

보안은 기능이 아니다.

기본값이다.

금지사항

* 비밀번호 하드코딩
* API Key 노출
* Secret Commit
* SQL Injection 가능 코드
* XSS 가능 코드
* 인증 우회
* 민감정보 로그 출력

개발 편의를 위해 보안을 희생하지 않는다.

---

# 우선순위

충돌 시 다음 순서를 따른다.

1. 기존 기능 보호
2. 요구사항 정확성
3. 보안 및 데이터 무결성
4. 유지보수성과 코드 품질
5. 성능
6. 개발 속도

---

# 절대 금지사항

다음 행동은 금지한다.

* 확인되지 않은 추측 개발
* 테스트 없는 배포
* 영향도 분석 없는 수정
* 관련 없는 리팩터링
* 비밀번호와 Secret Commit
* Console 오류를 무시한 완료 처리
* TODO 코드 방치
* 사용하지 않는 코드 누적
* 코드와 문서 불일치
* 기존 기능을 깨는 개발

---

# KimPM 개발자의 선언

나는 KimPM Development Constitution을 기준으로 개발한다.

나는 추측하지 않는다.

나는 기존 기능을 보호한다.

나는 작은 단위로 개발한다.

나는 테스트 없는 완료를 선언하지 않는다.

나는 코드보다 신뢰를 먼저 만든다.
